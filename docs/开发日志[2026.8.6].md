## Plan / 策划

### v1.2.0：迈向成熟全栈系统的第一步 — 数据库改写 + 任务管理板块

目标需求（对应 mission.md 第 4 项）：
- 前端 localStorage / IndexedDB 中的待办、随手记、音乐数据没有后端对应表，先补齐数据模型（新增 Todo / Note / MusicTrack），实现数据落库
- 在左侧工作区第一栏新增"任务管理"板块，包含：任务名、目的、关联知识、是否完成
- 支持列表视图与时间线视图两种查看方式
- 任务重要性分三档（第一层/第二层/第三层），高层级任务可拆分包含多个低层级任务（parentId 自关联）
- 每个任务的关联知识（关联文件/随手记）可与用户存储的资料互相插入关联，点击任务即直接显示关联目标

方案决策：
- 沿用 Prisma + SQLite，新增数据模型与既有 User / File 建立外键关系；Task 通过 parentId 自关联实现多级拆分，TaskLink 连接 Task 与 File / Note
- 服务端操作统一收敛到 Server Actions（src/actions/），前端 Zustand store 改为调用后端接口，本地旧数据在首次加载时自动迁移
- 任务管理为独立路由页 /dashboard/tasks，侧边栏"工作区"置于"我的文件"之前
- 时间线视图按截止日期分组（逾期/今天/明天/本周内/具体日期/未设置日期）

## Questions / 瓶颈点

- SQLite 单机数据库：任务/关联数据落库后仍受 SQLite 并发写与单机部署限制，正式上线建议迁移 PostgreSQL，Prisma 已抽象数据层，成本主要是方言差异与数据导出
- 任务树递归：getTasks 一次性拉取全部子任务，任务量极大时查询与序列化开销上升；后续可改为懒加载子任务或分页
- 时间线视图目前仅按截止日期静态分组，未支持拖拽调整日期与自动滚动到今天；优先级排序与日期排序的优先级规则还需细化
- TaskLink 关联面板每次展开需拉取全部文件（pageSize 200），文件量大时建议改为服务端搜索

## 补充更新 [2026.8.7]（测试反馈修复，不更新版本号）

### 修复内容

一、时间线视图无法标记任务完成

- 现象：按时间线查看任务时，任务行的勾选图标仅作展示，无法点击切换完成状态
- 修复：`src/app/dashboard/tasks/page.tsx` 时间线视图的完成图标改为按钮，点击调用 updateTask 切换 done 并刷新列表，与列表视图行为一致

二、任务列表新增拖拽自定义排序

- 背景：任务默认按创建时间排列，无法自定义顺序
- 方案：Task 模型新增 sortOrder 字段（同级排序），任务创建时追加到同级末尾
- 修改文件：
  - `prisma/schema.prisma` — Task 新增 `sortOrder Int @default(0)`，已执行 `npx prisma db push`
  - `src/types/index.ts` — TaskItem 新增 sortOrder
  - `src/lib/validations.ts` — 新增 reorderTasksSchema（items: [{ id, sortOrder }]）
  - `src/actions/tasks.ts` — serializeTask 输出 sortOrder；getTasks 顶层与子任务按 sortOrder 升序（次级按 createdAt），移除原先按优先级/截止日期的硬排序；createTask 自动取同级最大 sortOrder + 1；新增 reorderTasks 批量更新排序（事务）
  - `src/app/dashboard/tasks/page.tsx` — 列表视图每张顶层任务卡片外包 draggable 容器，悬停显示拖拽手柄（GripVertical），拖拽时卡片半透明、悬停目标高亮，释放后本地重排并调用 reorderTasks 持久化
- 说明：子任务在同级内同样按 sortOrder 排序，跨层级拖拽暂未支持，列入后续优化
- 附带修复：时间线视图分组逻辑中"未设置日期"分组被重复添加导致 React key 冲突、分组重复渲染，已修正（循环 groupMap 时排除 no-date，最后统一追加一次）
- 验证：`npx tsc --noEmit` 与 `npm run build` 均通过；浏览器实测时间线完成标记、列表拖拽排序与刷新后顺序持久化均正常
