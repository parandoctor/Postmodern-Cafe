# 开发日志 [2026.10.8 - 1.3.0]

## Plan / 策划

目标需求：
- 文件管理四个板块（我的文件 / 收藏夹 / 最近使用 / 回收站）补齐为可用页面，点击左栏二级目录必须真实切换
- 背景壁纸自定义修复：上传后必须立刻可见、刷新后仍在，不受默认工作台面板遮挡
- 音乐盒本地音乐上传修复：解决上传大体积音频报错 "Unexpected end of form"
- 文档与版本号同批提交（开发日志 / 版本文档 / README / package.json）

方案决策：
- 文件管理子视图改为独立路由，不再依赖 URL query + popstate 事件
  - /dashboard/files 我的文件、/dashboard/categories 分类管理、/dashboard/favorites 收藏夹、/dashboard/recent 最近使用、/dashboard/recycle 回收站
  - 左栏二级目录直接 Link 到路由，选中态由 pathname 推导，避免 query 变化不触发重渲染
  - /dashboard/files?tab=xxx 保留兼容旧链接
- 壁纸保存走"体积红线 + 持久化容错"双保险：收紧 data URL 上限，写入 localStorage 失败不再抛错
- 壁纸可见性通过 data-wallpaper 属性 + 半透明面板 + 遮罩实现，D5 视觉结构不变
- 音乐上传改走 Route Handler（不受 Server Action bodySizeLimit 限制），前端 fetch 直传

技术要点：
- App Router 客户端软导航不会触发 popstate，旧的 window.addEventListener("popstate") 方案在 ?tab= 切换时完全失效，是四个板块"打不开"的根因
- 子视图改为真实路由后，选中态、深链接、前进后退全部由框架保证
- 壁纸保存失败原因为 localStorage 配额溢出：persist 中间件写盘抛错会冒泡到上传回调，被 catch 当作"优化失败"并静默吞掉
- 大音频失败的根因是 Server Action 请求体上限，Route Handler 无该限制

## Target / 目标需求

- 左栏二级目录五个板块点击即可切换，页面内容与选中态一致
- 我的文件 / 分类管理 / 收藏夹 / 最近使用 / 回收站深链接可直接访问，未登录仍跳转登录页
- 自定义壁纸上传后立即铺满工作台背景，刷新后保留；默认背景可一键恢复
- 本地音乐上传成功入库并可播放；失败时界面给出明确原因
- npx tsc --noEmit 与 npm run build 通过；关键路由 HTTP 冒烟通过

## Questions / 瓶颈点

- 壁纸仍存 localStorage，单张图体积与账号下其他本地数据共享配额，过大图片会被压缩或提示换图
- 音乐上传接口把整个音频读入内存后再落盘，超大文件会占用较多内存，后续可改流式写入
- 文件管理上传仍走 Server Action，上限已提到 110mb，超过该体积需改用分片上传接口

## Follow / 优化拆解

1. 壁纸迁移到 IndexedDB 或后端存储，彻底解除体积限制
2. 音乐上传改为流式写入并显示上传进度
3. 文件管理统一改用 /api/upload/chunk 分片上传，支持超大文件与断点续传
4. 文件管理四个板块补齐排序、批量操作与空态引导
