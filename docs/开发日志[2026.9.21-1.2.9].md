# 开发日志 [2026.9.21 - 1.2.9]

## Plan / 策划

目标需求：
- 后台系统改为 D5 三栏结构：左栏导航（工作区 / 私有空间）、中栏工作台、右栏读数面板
- 文件管理五个子视图改为左栏二级目录：分类管理 / 我的文件 / 收藏夹 / 最近使用 / 回收站
- 分类管理重新设计：取消颜色分配，改为自定义分类名 + 重要性四档（核心 / 重要 / 常规 / 归档），同档内可拖拽排序
- 背景音乐与音乐盒完全独立：各自状态与音频实例，可同时播放，不再互相暂停
- 音乐盒默认完全空库，界面与文案不出现任何具体歌曲名
- 品牌保留「后现代咖啡馆」，不引入其他品牌标识

方案决策：
- 重要性使用 Int 0-3 存储（3 核心 / 2 重要 / 1 常规 / 0 归档），排序为 importance desc + sortOrder asc
- 分类详情路由由 [color] 改为 [id]
- 深色主题覆盖工作台关键页，通过 next-themes 的 class 模式切换
- 本地离线构建：移除 Google Fonts 依赖，改用系统字体栈
- 仅本地开发与测试，不推送 GitHub、不创建 PR

技术要点：

- 分类详情页直接使用路由 id 查询，避免依赖全局 store 造成空数据

## Target / 目标需求

- 后台三栏结构与 D5 细线网格视觉落地
- 分类管理无颜色选择，支持自定义名称与重要性
- 分类详情按 id 正确过滤文件
- BGM 与音乐盒可独立播放互不影响
- 音乐盒空库状态正常，无具体歌曲名
- npx tsc --noEmit 与 npm run build 通过

## Questions / 瓶颈点

- Google Fonts 在无外网环境下构建失败，改为系统字体栈解决
- build 与 dev 交替会污染 .next 缓存，测试前需清理缓存
- 历史分类数据迁移后重要性默认常规，需要手动调整

## Follow / 优化拆解

1. 深色主题可扩展到任务时间线、今日任务、音乐盒与个人中心
2. 重要性支持批量调整与快捷键
3. 分类拖拽可支持跨重要性分组
4. 音乐盒可增加空态引导与本地曲库统计
